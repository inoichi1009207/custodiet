## 第 0 步:接受三条世界观(否则后面全走样)

**0.1 你在建一个会审判你自己的系统。** 每条规则上线后第一个拦住的人就是你。
这不是设计失误,是这套系统的存在方式。你会想绕它——那一刻恰好证明它有用。
不许留只有你知道的后门。

**0.2 判据只有两张脸,优先级钉死。**
- **动作面**:工具调用的名字与入参。**来源较清晰的意图事件**——只证「请求过」,不证获准/成功/命中(真要证成功须回执通道,见第 1 步注)。
- **文本面**:正文里的关键词。召回实测 1/10~2/10,且唯一命中的常是你自己写的夹具句。
**能用动作面就永远别用文本面**;被迫用文本面时,把它定位成「绊线」——打中算赚,
不承诺覆盖,并且**永远不拿它的沉默当证据**(null 只能读作「未观测到」,不能读作「没发生」)。

**0.3 完成的定义先于工作。** 动手前先立验收条件(一条命令能列出来那种),收尾逐条对照。
没有验收条件的活,做完的标准是「你感觉做完了」——那正是要建闸防的东西。

## 第 1 步:立输入面 → 产物 `lib/gate-ctx.mjs`

**形状(照抄):**

```js
export function buildCtx(entries, extra = {}) {
  // 只收两种东西:assistant 的 text 块 + tool_use 的 {name, input}。
  // tool_result 一个字节都不进来——输出面=伪造面(见本步事故)。
  return {
    text,            // 本轮 assistant 正文(合并官方 last_assistant_message,transcript 会落后)
    actions,         // [{name, input}] 原始工具调用
    bashCmds, commits, writes, reads, agents, toolNames, skills, written,
    didCommit: () => commits.length > 0,   // 只证「发起过」,不证成功——写进天花板
    window: () => {...},   // 跨轮窗口:**恒在场的惰性函数**,缺窗口=调用返回 null。
                           // ⚠️ 函数属性永不 === undefined ⇒ 它**不走** requires 三态检查
                           //   (2026-08-23 外部评审抓到旧稿把两套模式抄串)
    batchGoal,       // 三态注入(见下),字段过 quoteUntrusted 再出闸
    pLedger,         // 同上
  };
}
```

**三态铁律(每条注入通道)**:`undefined`=通道没接(调用方缺陷)⇒ 规则报 **UNKNOWN,阻断项照拦**;
`null`=接了、查过了、确实没有;对象=有。**把前两态压成一个是 fail-open 之母**
(事故:「通道没供」被读成「确实没武装」,47 条自测全崩才发现)。再细一层:
**文件不在(null)与文件坏了(undefined)也是两件事**——坏账必响,别把损坏洗成正常。
载体=规则的 `requires` 字段+引擎统一检查,**不是**每条规则手写 if(那是被判死的原始写法)。
**适用边界**:三态铁律只管**值通道**(batchGoal / pLedger 这类直接挂值的字段);
window 这类**函数通道**不受 `ctx[k] === undefined` 覆盖——「没接」由构造期保证恒在场,
「取不到」用返回 null 表达。**别把函数字段写进 requires 又指望三态兜底**。

**注入面安全(v1 整个漏了这层)**:任何从磁盘读进 ctx 的字符串都是**不可信输入**,
而阻断消息是喂给模型的最高信任通道——实测过往批条件文件里植入 `SYSTEM OVERRIDE:` 成功。
缓解=`quoteUntrusted`(截断+压平换行+围栏),**在进 ctx 时做,不指望调用方记得**。
注意它只是**降低**注入面,不构成信任边界——更强的形态是高信任通道只回显内部 ID/摘要,原文留审计日志。

**事故(为什么 tool_result 禁入)**:306 次「跨模型复核」命中里只有 16 次是真调用,
其余全是文本/结果里出现了字面量。代价(闸看不见执行结果,只看得见发起)写进天花板,不许**偷偷**补——正道是独立的**回执通道**
(receipt:经 provenance/类型/大小校验后进入结构化字段,不混自由文本判据;本仓此通道欠建)。

**检查点**:`node --no-warnings lib/gate-ctx.mjs --self-test` ⇒ `ctx 自测 N/N`
(自测必须含:没给 priorEntries ⇒ window() 为 null;注入 null ≠ 注入 undefined)。

## 第 2 步:立引擎 → 产物 `lib/gate-registry.mjs`

**runRules 契约(照抄):**

```js
export function runRules(rules, ctx) {
  const findings = [];            // 元素形状:{id, block, msg}
  // blocking 可为 bool 或 (ctx)=>bool。函数形只在**命中路径**求值;
  // UNKNOWN / detect 抛错两条路一律按 true 计(fail-closed)——真引擎同形(gate-registry 三处)。
  // (2026-08-23 外部评审抓到旧稿抄了会错:通篇 `!!r.blocking` 会让函数恒真,条件阻断永不生效。)
  const blockOf = (r) => { if (typeof r.blocking !== "function") return !!r.blocking;
    try { return !!r.blocking(ctx); } catch { return true; } };
  for (const r of rules) {
    const missing = (r.requires ?? []).filter((k) => ctx[k] === undefined);
    if (missing.length) { findings.push({id:r.id, block: typeof r.blocking === "function" ? true : !!r.blocking, msg:`[UNKNOWN] 缺:${missing}`}); continue; }
    let hits;
    try { hits = r.detect(ctx) ?? []; }
    catch { findings.push({ id: r.id, block: typeof r.blocking === "function" ? true : !!r.blocking, msg: "[判据自身抛错=阻断项照拦]" }); continue; }
    //   ⚠️ 抛错路径**不走 blockOf**,与 UNKNOWN 路径完全同式:函数形一律按 true
    //   (崩溃不许被返回 false 放行);bool 形保持原级——**非阻断项抛错=提示不升阻断**,
    //   真引擎自测明文钉着这一向(2026-08-23 codex 逮到函数形漏洞、grill 逮到 bool-false 分歧,两轮修齐)。
    if (!hits.length) continue;
    // 正常命中 ⇒ findings.push({ id: r.id, block: blockOf(r), msg: r.message(hits) })
    //   —— 函数形 blocking **唯一**被真正调用的地方在这儿。
    // 豁免:kind:"action" 拿到的是剥了文本的 ctx —— {...ctx, text:"", says:()=>false}
    // (否则「说一句话」能满足 action 豁免;实测过一句话关掉三条通道)
    ...
  }
  return findings;
}
```

**装载期不变量(validateRules,每次真跑前必执行——造出来没接线=死件):**
INV-1 阻断项不得挂任何 text 豁免(且 `every()` 可被一条假 action 绕过,要逐条验 kind);
INV-2 law 锚点必须是非空字符串——**注意:「真实可解析」是应然,本仓实现尚未做到**
(实况:14 条死锚在债表挂着,校验只做了单向;别把未实现能力当已有铁律抄);
INV-3 正反例各 ≥1;INV-4 变异 ≥2;INV-6 `requires` 必须是字符串数组(类型错会炸整轮)。

**检查点**:`node --no-warnings lib/gate-registry.mjs --self-test` ⇒ 含**接受侧证人**
(至少一条「真调用发生所以放行」的用例——只有拒绝侧证人的引擎测不出「一律拦」)。

## 第 3 步:第一条规则 → 产物 `lib/gate-rules.mjs` 里一条完整 rule

**rule 对象形状(照抄,五件套逐项映射到字段):**

```js
export const RULE_X = {
  id: "X",
  blocking: true,                  // 或 (ctx)=>bool —— 条件阻断合法,但引擎必须按第 2 步 blockOf 求值:
                                   //   命中路径调用之,UNKNOWN/抛错路径按 true;裸 `!!r.blocking` 会让函数恒真
  law: "docs/laws/xx.md#锚名",     // 出生证①:它执行谁。锚必须解析得到
  requires: ["batchGoal"],         // 用到的注入通道逐个声明(三态由引擎统一管)
  detect: (ctx) => {...},          // 返回命中数组;空=未命中;永不自读磁盘
  exempts: [{ kind: "action", why: "...", test: (c) => ... }],   // 能不设就不设
  message: (hits) => `...出路写清楚...`,   // 出路必须便宜且具体
  mutations: [                     // 出生证④:放宽向、收紧向各≥1,各有证人
    { name: "放宽向:...", apply: (r) => ({...r, detect: ...}) },
    { name: "收紧向:...", apply: (r) => ({...r, detect: ...}) },
  ],
  cases: {
    pos: [{ text: "...", bash: "..." }],   // 出生证②:该拦的拦得住
    neg: [{ text: "...", bash: "..." }],   // 出生证③:不该拦的放得过
  },
  // 出生证⑤:失效条件写进头注(如「连续 20 批零命中 ⇒ 没在防任何东西,复议」)
};
```

**反例判别法(全文档最高密度的一条,原样保留)**:「压根没触发所以放行」**不算反例**。
把反例里的关键动作删掉再跑一次——**结果必须翻面**。不翻面的反例没有检验任何东西
(事故:16 条反例里 9 条是空的,四套独立夹具一致地空在同一处)。

**变异纪律**:把判据故意改坏,原有用例必须变红。变红不了的叫**等价变异**,
它揭露的是测试的盲区(事故:97 条变异里 40 条在「全绿」下存活)。只钉放宽一侧,
下次「顺手收紧过头」无人发现——两向各钉。

**检查点**:`node gate-migrate-check.mjs --migrate-check <id>` ⇒ 五项逐行「过/未过」,秒级。

## 第 4 步:搭验收台 → 产物 `gate-migrate-check.mjs`(夹具 DSL)

**夹具是一个迷你 DSL**,键名白名单 + 编译成 entries + **过同一个 buildCtx**:

```js
const FIXTURE_KEYS = new Set(["name","text","commit","write","written","bash","read","grep",
  "web","agent","mcp","skill","tracked","batchGoal","pLedger","prior"]);
// 拼错键**当场抛错**——静默丢弃是「夹具支持面不足伪装成规则缺陷」的传播机制(同族八次)
const mkEntries = (c) => { /* 每个键 → 一个 tool_use/text 块 */ };
const mkCtx = (c) => buildCtx(mkEntries(c), {/* 注入通道逐个转发,漏一个=夹具写了通道空着 */});
```

**铁律:判据要看什么面,夹具就必须能拼出什么面**——否则「夹具拼不出 ⇒ 用例必挂 ⇒
看起来像规则写错了」。每加一种判据面,同批加夹具键。

**每规则五项验收标准**:装载期过 / 正例全命中 / 反例全放行 / 变异各有证人 / 分歧已定性
(绿场第五项=「声明预期为空」即可)。

**检查点**:`node gate-migrate-check.mjs` 全量 ⇒ 退出码 0;1=用例失败,2=装载期拒绝。

## 第 5 步:接 harness → 产物 `hook-stop-closure.mjs` + settings 接线

**接线(照抄):**

```jsonc
// .claude/settings.json
{ "hooks": { "Stop": [ { "hooks": [
    { "type": "command", "command": "node scripts/hook-stop-closure.mjs", "timeout": 30 }
] } ] } }
```

**harness 职责清单**:stdin 收 JSON(含 `transcript_path`)→ 解析 JSONL、切出本回合
→ **读一次磁盘**(批条件/git tracked/义务台账)注入 ctx → `validateRules`+`runRules`
→ 输出:阻断=stdout 打 `{"decision":"block","reason":"..."}`+退出码 2;放行=退出码 0。

**四个工艺陷阱(每个都实撞过):**
1. **心跳别走 `additionalContext`**——官方语义是「keep the turn going」:每次干净通过都白烧一轮,
   直到撞官方 8 次连续续轮保护上限(注:「无限永动」的旧说法已被跨模型核实证伪,
   文档不许把源码已改正的结论写回来)。心跳走 stderr + append 落盘日志
   (「跑完无命中」与「崩了」必须可区分)。
2. **catch 自己不得再崩**(double-fault 铁律):catch 里重算规则表会抛、取 `e.message` 会抛
   (Proxy getter)、连「最后求救」的 stderr 行都会抛——逐层内层 try + 定值兜底。
   三层各被逮过一次,最深一层让进程裸崩、承诺的 exit(0) 永远到不了。
3. **每个入口文件加 IS_MAIN 守卫**——被 import 时不得执行主流程(同一 bug 犯过四次)。
4. **`node --check` 抓不到运行期引用错误**;抓它的是 eslint `no-undef`
   (两次实撞:缺 import 让判据静默全拒,eslint 一跑就报而没人跑)。

**逃生口纪律**:命名法统一(如 `STOP_CLOSURE_BLOCK_{id}=0`),开关表**由规则表派生**
(两张手写表必然漂移;对账只能发现漂移,派生才能阻止),配对账自测;
刻意无逃生口的规则注册成显式例外。**单人语境禁总闸**(一个环境变量关掉全部闸=不改代码即可让全部测试照绿地失效);
多人生产系统的正解不是禁,而是 break-glass:强身份+双人批准+TTL+告警审计。单条逃生口按上述派生建。

**检查点**:`node hook-stop-closure.mjs --dry-run <transcript.jsonl>` 看输出形状;
再手动触发一次真实 Stop,确认 transcript 里有 hook 记录。

## 第 6 步:验收哲学(绿场与迁移两条支线)

**绿场(从零建,多数读者在这条线)**:没有旧实现可 diff。验收=夹具五项 +
**真实历史回放**:拿本仓真实 transcript(几千片)跑规则集,逐命中**人工归因**——
每条命中标「拦对了/拦错了」,拦错的进误报台账并修。自己编用例自测=testing on training data。

**迁移(替换既有实现才走)**:影子回放,新旧并跑逐片比对。⚠️ 本仓的这套机器已随切换完成**退役成史料**(源码里有明文退役告示)——别对着退役段落抄活代码,抄结构即可。三条铁律:
① 两边喂**同一份世界**(同一快照注入两侧;一边现读磁盘一边用开跑快照=拿两个时刻互比,TOCTOU);
② 分歧**先逐片归因再白名单**,白名单绑成因谓词或切片指纹,禁止方向级 blanket
  (事故:第一版白名单被跨模型审计整个撤销——引用自己三天前的记忆写机制描述,没回源码重核);
③ **阻断性翻转单独一张表**(`EXPECTED_BLOCK_CHANGE`,按 `"block->prompt"/"prompt->block"`
  方向各配 null|谓词)——折进 id 级白名单会把「两边都命中但阻断性反了」一起放过。
数据结构:`DIVERGENCE_DIR` 值域 = `"new-only" | "old-only" | "both" | (piece)=>bool`,**漏填=全不放行**。

**节奏课(最贵的一课)**:**迁移标准 ≠ 切换标准**。每迁一条的门槛=该条五项(秒级);
全语料零分歧是**切换**门槛,每三四条统一跑一次。拿切换标准当每条门槛的实测代价:
一天一夜 19 个提交,真迁 2 条。

**规格级风险**:多个独立实现挡不住规格错——四个独立实现+35 条交叉夹具+五项验收,
一致漏掉同一个洞,因为洞在它们共同拿到的规格里(Knight & Leveson 1986 的现代版)。
对**规格本身**至少做一次跨模型对抗审。

## 第 7 步:量你自己(双台账)

- 误报侧:拦错了记一行(CLI 形如 `--fp <id> <为什么错>`);**分母自动记**
  (harness 每次命中 append 一行 `.gate-alerts.jsonl`——没有分母,误报率就是编的)。
- 漏报侧:抽查未命中回合(`--fp-miss <抽样数> <发现数>`),发现漏报即撤该规则「已验收」身份。
- 报表**永远打印 RECALL=UNKNOWN**——只量误报的系统会朝「少吵」而非「少漏」优化(可见性偏差)。
- **词表扩表是死路**(漏一个补一个,永远赶不上语言;实测扩一次当场与另一条规则打架)。
  语义类义务的真载体是**结构**:批条件、带失效期的债务台账。
- **一切登记带失效期,失效期配执行腿**(开工必经点机械列名到期项)。没有执行腿的失效期是装饰
  (事故:33 条债全部过期无人知晓)。到期=自动回 active:要么办,要么写明为什么不办(不许写「工作量大」)。

## 第 8 步:给你自己的八条决策规则(if-then,直接抄)

1. 要说「完成/已修/已跑」→ 先出示仪器输出。没有仪器输出就不说。
2. 要说「工具 X 有 bug」→ 先复查测法。`cmd | tail; echo $?` 读到的是 tail 的退出码——测量错先排掉。
3. 找到了仪器缺陷 → **不等于**被测对象错或对。修完仪器必须重测(事故:修完仪器后结论反转了两次)。
4. 引用 ≠ 使用。判据一律先剥引文(「」«»“”"…")再匹配,否则**处置一条告警的话语会再触发那条告警**(回声,实撞两族)。
5. **可被被审者现造的证据**,同轮自证不算证(立条件与销条件隔轮)。若证据来自独立执行器且绑定不可伪造的 digest,同轮亦可成立——隔轮买的是「来不及现编」,不是独立性本身。
6. 拿不准的方向按**代价不对称**倒:漏放流进下游难发现 ⇒ 往严;误拦当场可见、可人工放行 ⇒ 可接受。写明你倒向哪边、为什么。
7. 约束逐项拆成本,不整包套。「不要跑长任务」禁不了一次五秒的搜索——把禁令套在一个词上而不是逐项成本上,是判断缺席。
8. 比例感由人供给。闸是讨债人不是理财顾问:它知道欠什么,不知道现在还划不划算。把「**为什么不现在**」设为自检句——多数「下一轮做」的正确答案是「现在」。

## 第 9 步之二:如果你要自己写判活探针(CW 的判据本体)

本仓**不带**判活探针,于是 CW 这条规则在你这边是「规则在场、判据本体缺席」:每轮一条 UNKNOWN 提示、不阻断。

**先说清这个缺席有多贵**(比「一条噪声提示」重,独立复核逐条量过):

- **保护率为 0,而 README 仍把 CW 列在「它逮什么」里** —— 你永远拿不到 FAIL,「同一时刻只许一个写会话」在你这边没有触发层。这是**宣称型缺陷**:文档说有,实际没有。
- **它污染你的误报率分母** —— 每轮告警都会 append 进告警台账且 `ids` 恒含 CW,而第 7 步正是拿这份台账当误报率的分母 ⇒ 你的统计从第一天起系统性失真。
- **别把它记成误报** —— 规则消息里写着「若仍误报 → `--fp CW` 记账」。没装探针**不是闸拦错**,那是结构缺口;照着记会把 fp 台账也污染掉。

**不发布代码的理由只部分成立,照实说**:我们实现里真正 OS 特定的是**进程枚举**那一段,
其余(父子进程链上溯、pid 侧录、只读标记、活动窗口、fail-closed 兜底)看起来可移植。
但这只是**我们对自己那份实现的判断**,没有在别的平台上验证过——
session↔进程的绑定方式、转录目录的发现与格式,换个宿主都可能不一样。

**下面是我们踩过的坑与踩出来的接缝约定,不是一份完整规格。**
真要自己写,你还得自己定义清楚:输出的完整 schema、退出码表、「活跃写会话」的状态机
(进程活 ≠ 正在写;最近有对话 ≠ 仍持有写权)、会话与进程的绑定、转录目录的发现、
以及损坏/半截 JSONL 的处理。下面这些只覆盖「我们栽过的那几处」。

### 先把接缝契约定死(三条,踩过才知道贵)

**(a) 若你的协议用非零退出码表达「判出问题了」,那它是业务结果,不是执行故障。**
本仓就是这么约定的。消费方若只在 try 里取 stdout、catch 分支直接当执行故障处理,
就会丢掉它——于是**正好检出并发写的那一次,闸什么也没收到**。
本仓的做法是在 catch 里也解析 `err.stdout`。你若改用「永远 exit 0,判定只写进 JSON」也行,
**要紧的是两端对同一种约定**,而不是照抄我们这一种。

**(b) 超时预算分层,内层严于外层。**
枚举超时 < 探针超时 < harness 的 Stop 预算。本仓取的是 8 s < 15 s < 30 s,
**这是我们的配置不是通用常数**,按你的枚举实测耗时定。
内层比外层松时,慢路会被外层先掐断 ⇒ 你拿到 UNKNOWN,而 UNKNOWN 跟「没装探针」长得一模一样。

**(c) 三态别归一:没接线 / 接了但探测失败 / 判定结果。**
把前两者合并,依赖「探针在场」的下游契约就**永不触发**——你会宣称一个并不存在的保护。
⚠️ **本仓现在的公开协议其实没做到这一点**:它只有 `PASS/FAIL/UNKNOWN` 三个字符串,
「没装」与「装了但崩了」都落进 UNKNOWN,区别只在 `detail` 的**文本**里——
那不是结构化三态,消费方没法可靠分流。你从零开始的话,把这三种**作为独立字段**表达,别学这里。

**(d) 排除调用方自身会话——但「传个 session id 进去」不够。**
探针不排除自己,就每次都把自己报成并发写。常见做法是把当前会话 id 传给探针让它跳过。
但只要那个 id 是**入参**,调用方就能传别人的 id 进来,把别人从阻断面里摘掉。
所以还需要一步:证明这个 id **确实绑定当前调用者**(例如由 harness 而非命令行提供,
或与一个不可伪造的进程身份对上)。这一条我们自己也没做干净。

### 再说三个会让探针「判错了你也看不出来」的坑

写探针不难,难在它输出的是 PASS/FAIL,而不是「我为什么这么判」。下面每条都对应一次真实误判。
(第四类——「用例只有反例,把取数逻辑整个删掉仍全绿」——已写在第 9 步形态卡里,那条不限于探针。)

**① 别拿文件 mtime 当「有人在活动」。**
**机理**(不是文件系统问题,别按那个方向查):**在我们测试过的 Claude Code 转录里**,宿主会持续追加**非对话记录**——
成本统计、最后一次提示词缓存、心跳之类。这些写入同样刷新 mtime,
于是一个已经关掉不用的会话,在只看 mtime 的探针眼里**永远活着**。
**修法**:量转录里**最后一条 user/assistant 记录的时间戳**,不是文件 mtime。
实测差距:某个已闲置一小时的会话,mtime 与末条对话相差 3776 秒。

**② 转录文件很大,你会想只读头尾——那就必须标出边界。**
一份长会话转录可以到几十 MB,整读太慢,于是常见做法是读头 N KB + 尾 M KB 拼起来再倒序扫描。
坑在于:**当最后一条记录是一行超过 M KB 的巨型工具输出时**,尾段整块落在那一行内部、不含任何对话行,
倒序扫描会一路穿进**头段**,捡到**会话开头**那条消息——一个有效但极旧的时间戳,于是正在干活的会话被判死。
实测:60 MB 的转录里有 62 行超过 256 KB;头段首条与真实末条相差 5 天。
修法(我们用的一种,**不是唯一解**):拼接处插一行哨兵,时间戳只认尾段;尾段没有就退回 mtime(保守方向)。
也可以两段各扫各的,或干脆按**完整记录**反向读取。
另注意:尾段可能从半个 UTF-8 字符或半条记录开始,末行还可能正在被追加——两端的残行都要跳过,
否则你会把半条 JSON 当成一条合法记录去匹配。

**③ 第 8 步规则 5「可被被审者现造的证据不算证」在这里有个具体形态。**
探针要回答「哪个进程是我自己」「哪个会话已声明只读」,最省事的来源是 harness 注入的环境变量、
它自己落的 sidecar 文件、命令行字符串——**而这些模型都能写**。它们不是凭证。

⚠️ **别学我们走过的弯路**:我们一度认为「这一面是 fail-closed,所以可以容忍可伪造的来源」,
理由是「伪造一个**死** pid 会被判成陈旧标记、照旧阻断」。**这个论证是错的,而且我们把它写进了注释**,
直到后来实测才发现:伪造一个**活** pid 的标记会让判定直接放行。
真正的教训不是「哪一面可以容忍」,而是:**「这条路径是 fail-closed」这句话本身需要判据**,
而判据要覆盖伪造者能选的**全部**取值,不能只验你想到的那一种。
写下「此处安全,因为 X」之前,先问「X 覆盖了攻击者的全部选择吗」——
**不成立的安全声明比洞本身更坏**,下一个人会照着它相信这面已经守住(我们在同一个项目里犯了四次)。

至于怎么办:同一个取值函数若服务多种判据,给它显式开关(`trustEnv: false` 之类),
让每处调用各自声明取信门槛,而不是共用一套。信任根该放哪儿是另一个设计题——
进程表的父子链是一种选择,受保护的 broker、OS 级锁、带认证的 sidecar 也都能承担,
取决于你的威胁模型与部署形态。

> 天花板:以上四条只覆盖「探针自己判错」这一类。
> 「探针的判据源本身可被伪造」是另一个问题——判活的几个判据源(标记文件、pid 侧录、转录正文)
> 通常都在被判断方的写权限内,想彻底解决要把信任根移到操作系统的进程表那一层。
> 是否值得做,取决于你的威胁模型:如果唯一能伪造的人就是你自己和你的 agent,而两者都没有动机,
> 这一条可以只登记不修——**但要给它一个失效期,没有期限的「已知未修」等于静默改规矩**。

## 第 10 步:收尾的定义(什么叫「建完了」)

**绿场**:全部规则五项过 + 真实历史回放逐命中归因完毕 + 双台账在线 + 逃生口对账过。
**迁移另加**:切换判定五条,写于迁移**开始前**,不得事后放宽——
① 全部规则已迁 ② 装载期不变量全过 ③ 每条规则 ≥1 次真实流量命中(结构上打不着的走
**用户亲签例外**,附机器证明) ④ 未指名分歧=0 ⑤ 变异全被逮住(机器化身:`--cutover-check`,
别手工核对散文表)。五条全 GO 后:**删掉旧实现**(僵尸代码也是债,这一步最常被跳过)、
回退线=git revert 单个 commit、不留总闸开关。

## 天花板(照抄时连这节一起抄)

- 这套方法能把 22 条判据里的 **0 条**做成「完整可机械核定」——ctx 没有工具输出、没有用户语境,
  部分条款存在「两个真实情形投影成相同 ctx 而真值相反」的构造(不可区分世界),原理上核不了。
- 闸测不了「你对闸规则的错误建模」——预测闸的行为之前,跑它。
- 「对告警的正确处置」本身不可核定。所以这套系统最好的搭档不是更多的闸,
  是一个会问「为什么过了/为什么拦/为什么不现在」的人。
- **Stop 面的闸只能产「返工」,产不了「导航」**:为过闸而跑的外审,结论**恒到达在动作之后**;
  要让它改变动作,得另起**事前层**(不在本件内)。
  实证(2026-09-16):把一条「动承重面前提醒跑外审」的规则挂成**非阻断提示**,它确实按时响了
  ——而那一刻编辑**已经执行完毕**,提示只是给已发生的事加了个注脚。同日另一组数据:
  一整天 13 个批全是收尾才外审,外审**连续三轮推翻前一批的修法**,其中两条漏洞是那批自己刚装进去的。
  业界对这一层有成熟叫法与量化:pre-action authorization(事前授权)与 post-hoc evaluation(事后评估)
  是**两件事不是二选一**——某独立测评里社会工程攻击在宽松策略下成功率 74.6%、在事前授权闸下 0%。
  ⚠️ 但**事前层不能抵扣事后层**:前置审的是设计,后置审的是实际 diff;
  一次抽象的开工审计不该永久豁免后来实现里的漏洞。

## 未覆盖维度(跨模型审计点名,本仓已入债表限期)

- **威胁模型与控制面**:本仓的闸脚本/settings/台账全在被审 agent 的写权限内——防蓄意绕过须把
  控制面移出 agent 写权(CI/宿主策略/独立服务);transcript 路径直读、日志无 redaction 同族。
- **并发与命名空间**:状态文件无锁、无 session/worktree 命名空间、无幂等键——单写会话规范撑着,多会话即坏。
- **性能预算**:每轮多次全量读 transcript,无 p95 目标、无增量消费、无 per-rule deadline。
- **回执通道**:见第 1 步注——「已跑成功」目前原理上核不了。
