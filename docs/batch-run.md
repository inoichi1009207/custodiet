# 发车脚本 `scripts/batch-run.mjs`

## 做什么

把一句话交出去,让一批活自己跑到关账。脚本按顺序做这几件事:开批 → 拉起无头执行会话 → 重跑开批时登记的检查验收 → 不过就用同一个会话回修(至多三轮)→ 过了就并回基分支、关账。任何一步判不了,就停下,生成交接文件并写明卡在哪。

它只把已有的件接起来:开批、验收、关账、交接用 `batch-goal`,外审作业读 `codex-run` 的作业台账,私仓名单读 `gate-install.json`。它不改这些件的判决。

只用于本地、可逆的批(核对分级 T0 / T1)。会动线上内容的批不要用它发车。

## 命令行

```
node --no-warnings scripts/batch-run.mjs
  --batch <批号> --instruction "<用户原话>"
  --cond "<条件>" [--check "<命令>" [--expect "<子串>" | --expect-re "<正则>"]] [--cond …]
  [--finish-line "<终点线>"]
  [--max-turns N] [--max-budget-usd M] [--cap-usd T] [--deadline-min D]
  [--model <名>] [--judge-model <名>] [--no-merge] [--push <远端名>] [--handoff-out <路径>]
  [--same-error-limit N]

node --no-warnings scripts/batch-run.mjs --status [<批号>]
node --no-warnings scripts/batch-run.mjs --self-test

node --no-warnings scripts/batch-watch.mjs --replay <日志文件…> [--limit N]
node --no-warnings scripts/batch-watch.mjs --self-test
```

- `--cond` / `--check` / `--expect` / `--expect-re` 的写法和 `batch-goal --arm` 一样,原样透传。至少要有一条 `--check`:验收的硬门只认可执行检查,没有检查就拒绝发车。
- 上限的缺省值:`--max-turns 80`、`--max-budget-usd 8`(每次拉起)、`--cap-usd 20`(整批累计,含回修和方向复核)、`--deadline-min 90`(整批墙钟)。
- `--judge-model` 缺省 `opus`;`--model` 不给就不传,用 claude 的缺省模型。
- `--same-error-limit N`:看守的阈值,非负整数,缺省 3;`0` 关掉看守。见下面「看守」一节。
- `--no-merge`:关账但不并回基分支,工作树和分支都留着。
- `--push <远端>`:并回之后推基分支。只有远端地址的仓名在 `gate-install.json` 的 `privateRepos` 名单里才推;不在名单里就不推,结果里记一行「未推送」,照常关账。
- 要在仓的主 checkout 根目录发车,HEAD 要在一个分支上(这个分支就是基分支)。

## 流程

1. **发车前检查**。任何一条不过就退出 2,什么都不留:当前目录是主 checkout 的根(不是 linked worktree);HEAD 在分支上;批号只含字母、数字、`_`、`.`、`-`;有 `--check`;找得到 Git Bash 和 claude;工作树目录、分支、这个批号的运行状态都还不存在;没有别的发车在跑。
2. **建工作树**。`git worktree add <主树>/.claude/worktrees/batch-<批号> -b batch-run/<批号>`,从当前 HEAD 起。收尾闸只认 `.claude/worktrees/` 下的工作树批状态,所以位置是固定的。
3. **开批**。先生成执行会话号,在工作树里调 `batch-goal --arm`,带上指令、终点线、整批花费上限、截止时间和全部条件。子进程的 `CLAUDE_CODE_SESSION_ID` 设成执行会话号,批状态的武装者因此是执行会话。发车方自己的会话号(本进程环境里原有的那个)记成指令所在的会话。
4. **拉起执行会话**。`claude -p --output-format stream-json --verbose --permission-mode auto --max-turns N --max-budget-usd <本次上限> --session-id <会话号>`,工作目录是工作树,提示词走 stdin。提示词写着用户原话、逐条条件和检查命令、终点线、约束(只做本批范围内的事;不放宽条件;不开批、不结清、不推送、不合并、不切分支)和收尾要求(全部提交、登记成果与决定、最后一条消息逐条写 `条件N:达成` / `条件N:未达成:<理由>` / `条件N:不适用:<理由>`)。不用 `--dangerously-skip-permissions`,无人值守时的围栏是 auto 模式的权限分类器。
   执行会话跑着的时候,看守在读它的输出(见「看守」一节),命中就杀掉执行会话。
5. **分类**。被看守停下的 ⇒ 空转,不看别的(进程是被杀的,退出码和 `result` 事件都不可信)。其余按最后一条 `result` 事件分:退出 0、`is_error` 假、`subtype` 是 `success` ⇒ 跑完了,去验收;`error_max_turns` / `error_max_budget_usd`,或到整批截止时间被杀 ⇒ 到上限;`is_error` 真而 `subtype` 是 `success`,文字像额度提示 ⇒ 等额度;同样形状但文字不像 ⇒ 失败;没有 `result` 事件或别的形状 ⇒ 判不了。除「跑完了」以外都停,不回修。
6. **验收**。四项都看,收集齐了再判:
   1. 工作树干净:没有已跟踪文件的改动,也没有未跟踪、未忽略的新文件。只有运行时面不算:`.claude/` 下名字以点开头的那一层(批状态、批台账、义务账、各份台账、本脚本的运行目录)和 `.claude/worktrees/`。`.claude/agents/`、`.claude/commands/`、`.claude/settings.json` 这类版本化内容照算。
   2. 硬门:在工作树里跑 `batch-goal --dry-check`。全过才算过。
   3. 逐条裁决:从执行会话最后一条消息里取。每条都要有,而且是「达成」或带理由的「不适用」。
   4. 外审作业:本批在工作树里发起过 `codex-run` 作业才看。每个作业等到终态(最长等到整批截止),只认结果件最后一个非空行:含「不用再审」算过,含「要改」算不过;失败、超时、读不到、不是这两种结论都算判不了。同一个 slug 只看最新的一个。作业台账件解析不了时(写入方不是原子写,会读到半截)先重读几次;还解析不了、而这个文件在开批之后动过,也算判不了;开批之前就没再动过的旧坏件跳过。脚本自己不发起外审。

   任何一项判不了 ⇒ 停。有不过项 ⇒ 回修。
7. **回修**。用同一个会话续:`claude -p --resume <会话号> …`,提示词列出不过项的原文(检查命令和输出尾部、缺哪条裁决、没提交的路径、外审结论行、结清被拒的原文),写明「回修第 k 轮,共 3 轮」。至多三轮。第二次验收不过时(发第 2 轮回修之前)先拉一次方向复核:`claude -p --agent _direction-judge`,输入只有用户原话、完成标准、现状(只写事实)、两次验收的不过项。它判「偏了」或「该停」就停,交接里附它的全文;判「在路上」就继续;拉不起来或读不出判定,记一行,照常回修。
8. **关账**。验收全过才做:
   1. 并回:主 checkout 还在基分支上 ⇒ `git merge --ff-only batch-run/<批号>`。基分支前进过、不能快进 ⇒ 在工作树里 `git rebase <基分支>` 一次,冲突就 `git rebase --abort` 并停;成功就重跑验收的第 1、2 项,过了再快进。主树有本地改动导致 git 拒绝快进 ⇒ 停(脚本不 stash、不 reset、不 checkout 主树的东西)。
   2. 推送(给了 `--push` 且没给 `--no-merge`):仓名在私仓名单里才推,推完 `git ls-remote` 回读,要等于本地基分支。
   3. 欠账探针:这次真的推了、主 checkout 又有 `scripts/verify-prod.mjs` 时,跑 `--debt-only`,没过就停。
   4. 结清:在工作树里 `batch-goal --clear --verdict "N=达成" …`。被拒(`BATCH-GOAL-CLEAR-REFUSED`)时看拒因:执行会话自己补得上的(检查没过、有没提交的改动、登记的决定或成果缺记录、名下还有开着的义务)当成一次验收不过,还有轮次就回修,没有就停;其余拒因(判不了工作树或义务、检查被改过、批身份或义务账对不上、配置在批内改坏)直接停,不回修。
   5. 清理:并回过的,先删工作树里的运行时残留(见「已知限制」),`git worktree remove`(不带 `--force`)再 `git branch -d`。失败只记一行。

## 看守

看守只管停,不判对错。执行会话空转时把它停下,交接里写明卡在哪。停的条件一共五条,前四条是「到线」,第五条是看守本身:

| 条件 | 谁来管 | 停下时的 `reasonCode` |
|---|---|---|
| 一次拉起的轮数到 `--max-turns` | CLI 自己 | `cap-turns` |
| 一次拉起的花费到 `--max-budget-usd` | CLI 自己 | `cap-budget` |
| 整批累计花费到 `--cap-usd` | 发车脚本,每次拉起前比 | `cap-usd` |
| 整批墙钟到 `--deadline-min` | 发车脚本,到点杀执行会话 | `cap-deadline` |
| 同一个工具调用报同样的错,连着出现 3 次 | 看守(`scripts/batch-watch.mjs`) | `watch-same-error` |

判据的精确定义:

- **同一个调用**:工具名相同,入参(JSON 序列化)逐字相同。入参顶层的 `description` 不参与比较:它是给人看的说明,模型每次重试都会改写(真跑实测:同一条命令原样连试 8 次,说明依次写成「attempt 1」到「attempt 8」)。
- **同样的错**:工具结果的 `is_error` 为真,错误文字归一后相同。归一是把连续空白折成一个空格、去掉首尾空白、取前 500 字。
- **连着**:严格连着。同一条线上先后到达的工具结果,连续 3 个都是它才算;中间夹了任何别的结果(成功的,或别的错)就从头数。一条线是主会话,或某一个子代理:事件带 `parent_tool_use_id` 的按它分线,各线互不打断,也互不合并。
- 找不到对应 `tool_use` 的结果忽略,不打断,也不计数。

看守只挂在执行和回修的拉起上,方向复核那次不挂。它挂在发车脚本逐行读执行会话输出的那一处,按事件驱动。命中时:日志里写一行,杀掉执行会话的进程树,这次拉起记成「空转」(`stalled`),和到上限一样停下、不回修。交接的「卡在哪」一节写明是第几次拉起、哪条线、哪个工具、入参(前 300 字)、错误(前 500 字)、连着几次。运行状态里这次拉起的记录和 `runs.jsonl` 那一行各有一个 `watch` 字段,没命中时为 `null`。被杀的那次拉起没有花费读数,照到上限被杀的口径记一行备注、按 0 计。

**3 怎么来的**:拿另一个项目的 15 份真实无头执行日志回放,共 1293 次工具调用、86 个报错的结果。同一个调用报同样的错,从没连着出现过第二次(最长连串是 1)。取 3,是给「瞬时错误原样重试一次」留一格余量。回放用的是 `batch-watch.mjs --replay`,它只打计数和工具名,不打日志里的原文。

**不做的两样**:

- 不按签名累计(同一个调用隔三岔五失败,累计到 N 次就停)。有的机器上装着会改写工具入参的钩子:不带 `timeout` 的 Bash 调用会被权限检查拒一次,带上再发就过。累计口径会把这种正常节奏判成空转。
- 不造定时器,不轮询日志文件。看守挂在本来就有的逐行读取上。完全没有输出的挂死,由整批截止时间兜住。

代价不对称:该过的批被看守误停更贵(人要多说一句话),所以判据拿不准时往「不停」那边偏。漏掉的空转有轮数、花费、截止时间三条到线兜底。

**怎么关**:`--same-error-limit 0`。也可以把阈值调高,比如 `--same-error-limit 5`。

**停下之后怎么知道**:实测(2026-11-26,claude 2.1.327),无头执行会话结束时,`Notification` 钩子不响,`Stop` 和 `SessionEnd` 钩子会响。所以「停下了」这件事靠的是:发车命令一结束,发车方的会话就被原生机制叫回来读结果行。脚本不另造通知通道。

## 什么时候停

| 原因(`reasonCode`) | 什么情况 |
|---|---|
| `cap-turns` / `cap-budget` | 一次拉起撞了轮数或花费上限 |
| `cap-usd` / `cap-deadline` | 准备再拉起一次时,整批累计花费已到 `--cap-usd` 或已过整批截止时间;或者执行会话跑到截止时间还没结束(到点连子进程一起杀掉)。这两条上限管的是「不再拉起、不再等」:执行会话已经正常结束的那一次,验收和关账照常做完,不因为刚好用到线而作废 |
| `watch-same-error` | 看守命中:同一个工具调用连着 3 次报同样的错,执行会话被连子进程一起杀掉(见「看守」) |
| `quota` | 撞账户额度;等额度恢复再接着干 |
| `failed` / `unknown` | 执行会话报错,或结局判不了 |
| `accept-unknown` | 验收有一项判不了(检查跑不起来、外审作业失败或超时、结论行认不出) |
| `repair-exhausted` | 三轮回修后验收仍不过 |
| `judge-off` / `judge-stop` | 方向复核判「偏了」/「该停」 |
| `rebase-conflict` / `merge-refused` / `main-moved` / `merge-unknown` | 并回基分支走不通 |
| `push-failed` / `push-mismatch` / `probe-failed` | 推送失败、回读不一致、欠账探针没过 |
| `clear-unknown` / `arm-failed` | `batch-goal --clear` 出了拒清以外的错,或拒因不是回修得了的那一类;`--arm` 失败 |

停下时,脚本在工作树里跑 `batch-goal --handoff --out <路径>`,再往文件末尾追加一节「卡在哪(发车脚本写)」:停在哪一站、原因、每次拉起的分类与花费、最后一次验收的不过项、累计花费与上限、执行会话号、工作树和分支、怎么接着干。批不结清,工作树和分支都留着。接着干:进工作树,`claude --resume <会话号>`。

## 退出码与结果行

- 0:已关账;10:停下了(交接已写);2:拒绝发车(什么都没起);1:内部错误(尽量也写交接)。
- stdout 最后一行恒为 `BATCH_RUN_RESULT=<JSON>`。键:`batch`、`status`(`closed` / `stopped` / `refused` / `error`)、`reason`、`reasonCode`、`stage`、`rounds`(执行加回修的拉起次数,不含方向复核)、`acceptRounds`、`costUsd`、`sessionId`、`worktree`、`branch`、`handoff`、`ruler`(`--clear` 打出的主尺那一行)、`pushed`、`notes`。发车的会话只读这一行就够。进度信息都写 stderr。

## 落盘的文件

都在 `<主树>/.claude/.batch-run/` 下(已加进 `.gitignore`):

- `<批号>.json`:运行状态,原子写。记状态(`running` / `closed` / `stopped` / `error`)、本进程与当前子进程的进程号、会话号、工作树、分支、基分支与基点、上限(含看守阈值)、每次拉起的记录(每条带 `watch` 字段)。`status: running` 且进程号还活着,就是锁:同时只跑一个发车。
- `<批号>-r<k>.log`:第 k 次拉起的 stdout / stderr;`<批号>-judge.log`:方向复核。
- `<批号>-handoff.md`:交接(`--handoff-out` 可改位置)。
- `runs.jsonl`:每次运行结束追加一行:时刻、批号、状态、原因、每次拉起(分类、轮数、花费、耗时)、验收次数、方向复核结果、看守命中(`watch`,没命中为 `null`)、累计花费、模型、会话号、主尺、总耗时。

`--status [<批号>]` 只读地打印这些。

## 已知限制

- 真跑过的只有这些(2026-11-22,claude 2.1.327,便宜模型,一个没装闸的临时空仓):
  - 改一个文档的小批,一次过、并回、结清,跑了两次:106 秒 / 0.0125 美元,34 秒 / 0.0086 美元。
  - 检查命令必然不过的批:执行 → 验收不过 → 回修一轮 → 第二次验收不过 → 方向复核判「该停」→ 停下写交接。80 秒 / 0.0185 美元。
  - 没真跑过的:三轮回修用尽、撞上限、撞额度、推送与欠账探针、外审作业——这些只有按剧本行事的假 claude 自测;也没在装了闸的仓里跑过(执行会话里收尾闸会怎么拦,没有读数)。
- 临时空仓里量不出主尺:主尺要在发车方会话所属项目的转录里找那句指令,发车方会话不属于这个仓时找不到,`ruler` 会写「量不出」和原因,不影响关账。
- 本机若有钩子在权限检查之后改写工具入参(实测时有一个会给 Bash 调用补 `timeout` 的钩子),auto 模式会拒掉那一次调用,执行会话重发才过。它只多耗轮数,不影响验收结论。
- `--permission-mode auto` 在 auto 模式用不了的环境里会退回会先问的模式,无头会话里没人回答,动作会被拒;这时执行会话多半以失败或判不了收场,脚本会停下,不会误关账。
- 花费怎么记:续接会话(`--resume`)时 CLI 报的 `total_cost_usd` 是这个会话的累计值,而 `--max-budget-usd` 按本次拉起单独比(2026-11-22 在 claude 2.1.327 上实测:同一会话续接四次,读数单调增;累计读数已超过上限值时续接照常跑完)。所以脚本对回修轮按「本次读数减上一次读数」记账。将来 CLI 要是改成按次报,读数比上一次小时脚本会整笔记;读数恰好一次比一次大就会少算,这时兜底的是每次拉起的 `--max-budget-usd`。花费上限本身是 CLI 每轮结束才比的估算,会超一点。
- 「额度提示」的认法是一组词(`usage limit`、`quota`、`额度` 等),撞额度时的确切文字只实测过一次。认不出时按「失败」停,同样不回修。
- 外审作业的判活只看作业台账的状态字段;worker 进程死了而台账还写着 `running` 时,脚本会一直等到整批截止再按判不了停。
- `--clear` 在并回(和推送)之后才跑。它要是被拒、回修轮次又用完了,基分支上已经有这一批的提交,批却没结清;交接里会写明「已并回基分支」。
- 关账后清理工作树前,脚本会删掉工作树里的运行时残留:运行时面里的未跟踪文件(范围同验收第 1 项:`.claude/` 下名字以点开头的那一层,如批状态、批台账,其中开批与结清两行已镜像到主树),和结清时后台盲审写的 `clipboard/codex/fp-audit-last.log`。`.claude/` 下的版本化内容不在其内。只有工作树里**全部**未提交项都属于这两类时才删;混着别的未跟踪文件或已跟踪改动,就一个都不删,`git worktree remove`(不带 `--force`)照旧会拒,工作树留着,只记一行。
- 执行会话里的收尾闸照常生效。闸拦下会让会话多走几轮,算在轮数和花费上限里。
- 登记的检查命令自己会往工作树里写文件时(没被忽略的输出、日志):验收是先看工作树、再跑检查,所以这些副产物不会让验收不过;但关账后工作树里留着未跟踪文件,`git worktree remove` 会拒,工作树留下,只记一行。检查命令最好不落盘,或把输出写到被忽略的位置。
- 看守可能误停的一种情形:执行会话原样重试同一条命令等某样东西就绪(等服务起来、重试一次瞬时的网络失败),入参和错误文字都一字不差,连着到第 3 次就会被停。回放过的 15 份真实日志里这种原样重试一次都没出现过;真遇到了,用 `--same-error-limit` 调高或关掉。
- 看守认不出的空转(漏放,由轮数、花费、截止时间三条到线兜底):
  - 错误文字里带每次都变的内容(时间戳、进程号、耗时、临时文件名),归一后每次都不一样,认不出是同一个错。
  - 两个调用轮流失败(甲乙甲乙),不算连着。
  - 换着入参重试同一件事(比如每次改一点命令),不算同一个调用。
- 看守真跑命中过的只有一种造出来的空转(2026-11-26,claude 2.1.327,便宜模型,没装闸的临时空仓):指令要求原样重复一条必然失败的命令。第一次没命中——模型原样连试了 8 次,但每次都改写入参里的 `description`,那时的判据把它也算进了「同一个调用」;改成不比 `description` 之后重跑,第 3 次报错时被停,执行会话 19 秒后被杀,没有残留进程,交接写明了工具、入参和错误。真实任务里自然出现的空转还没遇到过。
