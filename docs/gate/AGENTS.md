# 闸规矩(公开版;底稿日期 2026-11-05)

> 本仓是收尾闸系统的源头。装了这套闸的仓作为安装方使用。
> 跨项目的协作规矩在全局规范;本文件只管闸怎么设计、怎么改、怎么验收。
>
> 公开版说明(这几行不是规矩):
> - 「全局规范」指维护者用户级的跨项目规范,本仓不带那份文件;你用你自己的。
> - 「用户」指给这个仓签字的人,「我」指执行的模型。
> - 带编号的 ADR 是源头项目的决策记录,没有随本仓发布。ADR 0009 的内容是代价模型:只数诚实遗忘,蓄意规避不计,误拦与漏放同价。
> - 文中提到的 `docs/error-list.md`、`docs/receipt.md`、`verify-laws`,本仓现在都还没有。

## 一、设计原则

1. **一条规则拆成五个部件**:触发、调度、取证交给代码;判断留给模型或审查者;**拒绝放在状态迁移那一步**(关账、推送、写债表、写法条)。不在每轮收尾时追着提醒。
2. **措辞只当触发器**:可以用措辞发现「这里有一句声称」,但不能拿措辞当证据,也不能让「写对暗号」成为出路。证据只认工具结果、git 事实、探针输出。
3. **义务是独立的记录**:换批、强制覆盖、泄压都清不掉;判不了一律按「开着」处理;模型不能自己把义务标成已清。
   - 自动重试由编排脚本计数,每条最多 2 次;超限就自动转成一行带失效期的欠账(默认 ≤ 当前批号 + 3),只通知,不要人批准。
   - **转欠账不等于完成**:报告里「已清」和「转欠账」分开列;转欠账也不能替代需要用户签的事。
   - 转欠账以后不再拦关账;到期没结,开批时自动列出,回到「开着」。
4. **出路必须走得通**:每个拒绝点都要有一条执行者能走通的出路。走不通的阻断会让无头 Agent 空烧到轮数上限。
5. **默认安静**:纯问答回合不交回执,闸也不说话。提醒只在内容变化时注入一次,一行摘要加一个文件路径。

## 二、规则怎么进来

1. **每条规则必须指向「出错清单」里一条真实出过的错**,并附转录位置。出错清单住 `docs/error-list.md`,每条一行:形态、首次出现的转录位置、防它的规则 id。
2. **例外**:防不可逆、凭据、对外发布这三类后果的规则,没出过事也可以立,但要在出错清单里写明「预防类」和它防的后果。
3. **每条规则配一个夹具**:先把错误引进来,看着它变红,再还原。光有绿色不算。
4. **指不到出错清单、又不属于预防类的规则,列为裁撤候选**。裁不裁由执行的模型主动判,不等用户点名:先做真阳性回放(第三节「删规则之前」),合并前照常过三路审查,事后在报告里并列报四个数。用户说过要留的规则不在此列。
5. **同一个病第三次出现**(出错清单里同一形态出现第三行),下一批的第一件事是判定「换机制还是继续补」,不能直接再补一次。
6. **绊线必须有人认领**:欠账表的「认领」一列写我或用户;没人认领的不许写。
7. **新增状态或人工步骤之前**,先查这种情况的历史频率,再看有没有现成机制能接住。

## 三、怎么改闸

| 时机 | 做什么 |
|---|---|
| 设计阶段(开工前) | 查外部先例,真取页;用 `xros:compile` 写出带检验命令的规格 |
| 写代码 | 测试先写,每个测试文件开头写清它防的是哪种失败;新代码先用 tdd-guardian 的对抗代理攻测试矩阵 |
| 每次提交 | 只跑机器检查:闸自测、`gate:accept`、回放。改动都在本批的分支或 worktree 里提交 |
| **合并回主分支之前** | 红队 + 误拦猎手(误拦猎手的 `--base` = 本批开工时的提交)+ codex,审**整批 diff**;回件绑定被审的提交范围,审后又改过就作废。这就是全局规范里「守卫语义改动先过跨模型复核」的落点:复核在合并这一步之前做完,不是每次提交都做 |
| 处理审查回件 | 回件要改的发现多于 5 条、或是同一份东西的第二轮回件时,分拣前先过方向复核:一个没看过推理过程的只读代理,只拿到用户原话、完成标准、现状和回件,对每条只问「不修它,完成标准还成立吗」;它判不修的,除非手里有退出码或测试结果证明必须修,否则不修、记一行;它判方向偏了或该停,就停下报用户。本批引入、且没有被判不修的问题当批修完;不是本批引入的,登记欠账;回件标「故意伪造」的漏放(只有存心绕闸才会这么写)不修、不登债,在处置记录里写一句「蓄意档,按 ADR 0009 接受」;修完以后只针对修改的部分复核,不重跑全面审查 |
| 什么时候停 | 同一个子系统连续三轮复核仍冒出**新形态**的问题,就停止局部修补,退回或转独立的设计复核 |
| 删规则之前 | 真阳性回放:台账里盲审判「拦对了」的记录逐条交新机制判,报「接住 / 没接住」 |

**验收要并列报四个数**:确认误拦、确认漏放、判不了、各属哪类错。只报阻断占比不算,因为删掉有效检查也会让这个数变好。

**每个新实现都要回答五个问题**:
1. 同一个失败事件发生时,依据什么事实发现它?
2. 哪一步自动执行?
3. 谁来判断?
4. 失败或判不了时,禁止哪个状态迁移?
5. 还有没有绕过的路径?

## 四、授权

0. **什么算「守卫语义改动」**:同样的输入,改前和改后闸的判决(放行 / 提示 / 阻断)不一样,就算。
   - 判定方法:用 `gate-replay.mjs` 拿真实转录和夹具,改前改后各跑一遍,比对判决。判决全部不变的(只改了消息文字、重构、注释、测试),不算。
   - 回放看不出来的三类,一律按语义改动算:钩子接线(`settings.json` 挂哪些钩子、匹配哪些工具)、权限的放行表和拒绝表、依赖生产事实的路径。
   - **不算的**:只跑机器检查。**算的**:合并回主分支之前走三路审查(第三节);合并后的报告附回放差异,写「新增阻断 N 处、减少 M 处」,各举两例,让用户一眼看出闸变严还是变松。
1. **判据过重时,可以自己修判据或判官**,事后报告。
2. **可逆的机械改动可以自签**,但合并回主分支之前要过跨模型复核;通道不可用就转为等用户签。
3. **发布到 custodiet 公开仓**:验收全绿、凭据扫描通过,就直接推,事后回读远端核对。翻可见性、删仓、`--force` 照旧停下问。
4. **改本文件的正文**,要用户逐字审。

## 五、改代码时必须同步的地方

- **规则的法条锚点**:新节名不能太短。匹配是双向子串,太短会误命中别的节,造成假绿。解析器现在只认标题和 `- **条名**`,不认 `1. **条名**`,写法要和解析器一致,或者同批改解析器。
- **锚点变绿只证明指针能解析**,不证明规则符合新的授权。改法时要同时核对规则的判定和消息文字。
- **`verify-laws`**:改法典的结构,要同批改它。
- **安装方专属的路径**,比如内容写入管线的脚本名、生产事实文件,一律做成安装方的配置,不写死在闸代码里。

## 六、收尾回执(交给安装方的执行者)

格式、字段、检查规则见 `docs/receipt.md`。**这个文件现在还不存在**,在它落地以前,以源头项目的设计稿第 2.3 节为准(该设计稿没有随本仓发布)。只有格式错可以「只改回执」;缺动作就补做或撤回声称;外部不可用就标 `blocked` 并登记欠账。
